# 游戏数据

静态定义保存在 `catalogs/`，由 `resource_catalog.py` 在对应模块首次加载时读取和校验，不执行数据文件中的代码。路径相对于项目目录解析，启动工作目录不影响资源加载。

| 文件 | 内容 |
|---|---|
| `blocks.json` | 方块 ID、名称、物理/接触属性、功能和像素图案 |
| `buffs.json` | 状态 ID、分类、参数描述、叠层限制、冲突、图标、已实现处理器名 |
| `costumes.json` | 默认时装 ID、尺寸和各动画状态的像素帧 |
| `interface.json` | 设置页帧率选项、地图编辑字段、标签、默认值和步长 |

前三个目录采用统一头部：

```json
{
  "schema_version": 1,
  "kind": "blocks",
  "entries": [{"id": 0, "name": "air", "name2": "空气", "is_solid": false}]
}
```

同一目录的 ID 必须唯一且保持稳定。方块字段对应 `BlockType`，状态字段对应 `BuffType`；缺省字段使用数据类型默认值，未知字段、非有限数值、错误颜色/图案及无效关联会被拒绝。JSON 里的数组在方块/状态定义中转换为元组；时装保留像素数组。`special` / `tick` 是程序中已有处理器的标识，新增数据不会自动实现新机制。

图案沿用三段格式：`["vector", [宽, 高], 指令数组]`、`["bitmap", 尺寸, 像素行]` 或 texture 格式。矢量指令支持 `fill`、`rect` 和 `circle`。RGB/RGBA 分量为 0～255；时装像素 `0` 表示透明，所有帧的行列必须匹配声明尺寸。

格式化数据：`python3 scripts/format_catalogs.py`。迁移前所有方块定义、图案、状态图标和时装帧都有哈希基线；运行 `python3 -m unittest discover -s tests -p test_catalogs.py -v` 验证属性及像素一致性。未来有意修改外观时应保留修改前后截图并明确更新相应视觉基线。

地图的运行配置仍放在 `maps/<目录>/config.json`，沿用地图编辑器保存/加载和 `map_config.py` 数值校验。生成地图的算法保留在 Python 中，内容定义和执行逻辑分离。

`interface.json` 中的 player 字段默认值是游戏角色预设的统一来源，由 `resource_catalog.player_defaults()` 校验加载；`player_factory.create_world_player()` 用于实际启动和地图审计，地图 config.json 的 player 值覆盖该预设。编辑器读取同一份默认值，避免仅保存默认配置就改变物理参数。

方块与Buff允许分包：`catalogs/extensions/blocks_*.json`、`buffs_*.json`使用相同的schema头部，启动时按文件名排序合并到主目录。包内及跨包ID均须唯一，不能覆盖旧ID；关联项在合并后统一校验，可跨包引用。显式传入独立JSON路径时仅加载该文件，避免隐式污染编辑/测试数据。

新增效果方块优先通过`buff_ids`、`buff_params_list`和`buff_durations`关联已有Buff，保持参数/持续时间按位置对应；接触时记录来源方块ID。`blocks_magnetic.json`中的439磁引花仅关联14，不含特殊效果处理器；磁引的执行由Buff和世界上下文负责。新增行为仍需实现消费者并验证真实来源、效果及清理。

旧目录哈希基线保留；新ID在`tests/fixtures/catalog_extensions.json`单独登记完整定义、像素及非美术字段哈希。美术生成器重建主目录时不读取/覆写扩展包；新增包使用独立生成器（例如`python3 scripts/build_magnetic_block.py`）。新增数据须同时更新相关审计器，使静态盘点覆盖运行时有效目录。

数值型Buff的空参数`[]`表示使用对应处理器已有默认值，`[0]`表示显式零，二者不同。不要给所有效果统一填`[0]`：这会抵消恢复、减伤、轻羽、带电等效果，还可能把周期效果压到最小间隔。flag型参数按既有契约处理。A80已把33种旧方块中的37个错误数值占位改为空参数，不全局重解释API零。

有意修改旧玩法字段须在`tests/fixtures/catalog_gameplay_changes.json`逐字段登记前后值与原因。目录测试先确认运行时值准确等于登记的after，再将该字段恢复为before，与原历史完整定义/非美术哈希比较；其他字段不能夹带变化。不可改写历史哈希来吞掉差异。`scripts/repair_buff_source_defaults.py`可重放A80迁移，遇到后续不一致编辑会拒绝覆盖。美术生成从当前玩法字段出发，仅图标回退轮廓使用历史像素，避免撤销功能修复或对精修图标重复加工。

Buff49的第一参数为有符号磁力响应倍率：空参数默认+1，正数正向、负数反向，0为中性且不受磁力，绝对值限于4；非有限数值不产生磁力响应。它控制角色对既有矿石场的响应，不是场半径（当前4格）。原386/403已明确使用[1]，411使用[-1]，通过同一Buff消费者产生不同效果。方向反转23独立于磁极方向；清明/铁意可免除操作反转，位移免疫仍独立屏蔽场力。身上与来源说明显示实际有效方向/倍率。

`python3 scripts/repair_magnetic_polarity_sources.py`可重放A84三处参数迁移；A80迁移重放会保留后续阶段的审查项，遇到同一字段的更新审查会拒绝覆盖。重放迁移与美术生成后须验证当前目录、所有审查项与历史基线都保持不变。

Buff4首参数单位为跳跃**高度**增加百分比，缺省50、显式0无加成，按实例层数计算高度倍率；不要把百分比直接乘在起跳速度上。`jump_height.py`根据当前世界有效重力（含13/54）、角色垂直阻尼和120Hz实际积分顺序反求自由上升所需速度。来源方块的既有jump速度倍率先合入基准；自动弹跳/弹射冲量保留，Space不会压低已有更强上升。刷新缓存最多256组，无加成时原速度直接返回。

该高度标定指无顶板、无额外外力、环境和Buff在上升期保持稳定的自由轨迹；液体、磁场等独立环境仍可改变实际结果。上下文未知或没有可表示有限顶点时使用能量关系的平方根速度回退；零垂直阻尼本身不能形成跳跃，保留基础速度。非有限Buff倍率不传播无限或NaN速度。无需修改既有方块/Buff目录和历史像素基线。

来源Buff的持续接触与叠层分开处理：同一世界连续接触同类方块为一次曝光，跨相邻同类格/循环接缝不增加层数，持续接触仍刷新参数、来源和时长；完全离开该类再接触或接触其他来源种类时可增加层数。`buff_contacts.py`统一处理此契约，无具体方块ID分支。角色复活/reset清理接触记忆，飞行清空环境接触；当前记忆只含正在接触的种类。

显式`apply_buff`/`BuffInstance.refresh`默认仍表示新获得，可正常叠层；`add_stack=False`明确只刷新已有实例，首次获得仍建立一层。单独清理Buff而仍在来源上时，随后接触可重新建立一层。21接触时长策略与22/51数值叠层独立由下述Buff行为规则定义；连续曝光计数本身不决定控制时长或减速曲线。

`data/rules/buff_behavior.json`在启动时经`buff_behavior.py`验证加载为不可变规则，按Buff编号配置`contact_trigger`（refresh/entry）和`stat_stacking`（linear/multiplicative）；缺省保持持续刷新和原线性百分比，严格拒绝未知Buff、重复ID、未知字段和策略。显式文件加载用于验证，不改变运行中的全局规则。

21配置entry：进入来源才施加，已有21时不续期，停留到期/主动清理后不重新施加，完全离开重入可再次触发；免疫阻止首次施加也消耗该次进入事件，免疫结束时停留不会延迟触发。显式API刷新仍按调用者给定时长；铁意40原冲突清理不变。22/51配置multiplicative：每层部分减速相乘，50%三层保留12.5%速度、40%三层保留21.6%；显式100%及以上仍为零。其他Buff继续原数值叠层，所有来源方块自动继承对应Buff策略，无来源ID分支。

53风步的加速由`wind_walk.py`处理，首参数缺省读取共享wind_walk默认0.5，显式0不加速；它限制加速上限，不直接改写移动速度倍率。充能计时/速度阈值/总速度上限沿用既有规则；存在有效输入时沿角色实际a_x方向加力（已包含23反向及8/40免疫），没有输入时保持原动量方向。持续刷新不因帧数叠层，暂停、到期和复活按既有生命周期清理充能。

Buff的`cleanup_by`是反向清理关系：例如9声明`cleanup_by=[15]`，15被接受获取或刷新时立即清除活动9；已有15时再获取9同样被拒绝。通用`buff_cleanup.py`消费此关系，无来源方块ID分支，`conflicts`仍表示获取者主动移除的目标。先检查诅咒/免疫/自身cleanup_by等准入条件，再执行主动冲突与反向清理，被拒绝的获取不能清理其他效果；内部仅对仍活动的目标调用移除回调，重复声明和回调连带移除不会重复回调。公共`remove_buff`的其他旧调用语义未在此全局重写。

Buff行为规则可选`control_locks`数组，动作限定horizontal/jump/climb/swim，默认空，严格拒绝重复或未知值，加载后为不可变tuple。`buff_controls.py`统一查询活动Buff；角色主动动作、WorldSession和上岸边界均消费它，重力/碰撞/环境作用和计时继续运行。59冻结配置四项限制、entry接触触发及cleanup_by40，`halt_motion`一次性取消旧速度/加速度、攀爬对齐和上岸过程，不用跳过物理实现冻结。

`data/rules/buff_reactions.json`由`buff_reactions.py`启动验证并缓存，按required_buffs、contact语义和result_buff关联，禁止具体来源方块ID。唯一cold_water规则要求51与真实水接触，2秒base_duration×2倍duration_multiplier产生4秒59。普通水不冻结，寒冷单独/仅蒸汽浸湿/蜂蜜/熔岩/伤害液体不触发。水谓词与原自动浸湿共用，不把can_swim一概当水。

反应每轮曝光仅尝试一次（免疫拒绝也消耗机会），持续接触不续时；必须离开真实水且15浸湿完全结束才重置，防水面抖动或净化后反复冻结。世界切换/复活/飞行清空反应记忆。已有更长/永久结果不被短规则覆盖。规则引用、类型、唯一ID、正数、有限乘积和下溢均验证；显式文件加载不污染运行缓存。新增59在独立buffs_frozen扩展包/新增ID哈希清单登记，原58定义及像素基线保持。

`python3 scripts/build_frozen_buff.py`可重建59与原生像素图标；`python3 scripts/audit_catalog_regeneration.py --output /tmp/regeneration.json`依次重放A80/A84迁移、美术生成与两个扩展生成器，逐步验证目录、规则、审查清单和消费者字节不漂移。运行重建会写目录，应与同时读取目录的测试顺序执行。
