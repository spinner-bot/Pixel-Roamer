# 传送落点与地图出口修复

## 实测问题

全地图扫描原有 21 个传送门，17 个目标会与实体或边界重叠。`(0,0)` 默认目标、整数格坐标被当作人物中心、目标装饰覆盖空间是主要原因。原始列表见 [修复前数据](evidence/2026-11-11_portals_before.json)。

继续追踪发现：无限森林的门被后面的检查点覆盖，实际地图没有这扇门；循环迷宫隐藏房的云台贴住天花板，冰宫宝藏室则完全封闭。只把角色传到空隙里仍会困住玩家，因此也验证实际走出房间。

## 逐图修改

- 宏大旅程：最后统一清理四组双向门的抵达空间，防止随机点缀再次填塞；目标采用人物中心坐标。未指定目标的展示符文明确返回入口，避免送到世界原点。
- 像素启程：森林落点站在地面上，冰宫落点避开珍珠实体；打通通往攀爬藤蔓的出口。
- 循环迷宫：避开云台、治愈水晶实体，修复跨循环边界的隐藏室出口。
- 无限森林：将门移到检查点旁，保留两者；目标避开湖岛树干。
- 冒险湾：终点附近两块传送门配置到终点信标上方，实际接触后通关。

引擎层对目标类型、有限数值、超大整数、地图边界和实体重叠作检查；循环坐标先归一化，再做几何判断。拒绝非法目标时保留当前位置，避免把一次配置错误放大成穿墙或崩溃。接触锁直到离开所有传送门后才解除，双向门静止不会来回振荡，走离并重新触碰后可以正常返程；重生清除此锁。

## 验证

恢复森林门后共 **22 个传送门**：全部从没有实体重叠的接触位置实际触发，目标与配置一致；随后模拟一秒，均存活、无实体重叠。冒险湾两处终点门实际设置通关标志。数据见 [修复后数据](evidence/2026-11-11_portals_after.json)，复现命令：

```bash
python scripts/audit_portals.py --output /tmp/portals.json
```

新增回归覆盖：双向门静止两秒不往返、移动离开再进入可返程、非法/NaN/Infinity/超大整数目标不移动不崩溃、循环目标归一化、重生清锁，以及迷宫房间/冰宫房间通过实际移动和跳跃走出。原神殿完整路线仍通过。完整 **119 项通过，31.472 秒**，编译与差异检查通过。

这验证了已检查的传送与两个房间出口，未宣称宏大旅程等所有旧地图均已完整通关。后续将继续检查地图生成的可重复性：若装饰随加载顺序变化，会让实测结果难以重现。
