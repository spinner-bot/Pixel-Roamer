# 固定时钟与帧率一致性

## 复现与原因

对五种地面施加相同方向力五秒，比较 30、60、144 FPS。旧流程先按显示帧执行加速度，再执行指数阻尼，阻尼本身虽按时间换算，施力与阻尼组合仍依赖帧长。雪地位移 9.856 / 11.166 / 11.982 格，末速度 1.993 / 2.261 / 2.429 格/秒；黏土位移 28.764 / 30.117 / 30.924 格。

## 修复

新增 `simulation.FixedStepClock`，固定 120 Hz、保留不足一步的余数；WorldSession 整体按固定步更新，包括状态、体力、游泳、攀爬、胜负和物理。显示帧只采样一次持续按键；跳跃请求留到下一个模拟步消费一次。帮助与页面暂停不推进时钟，更换世界重建时钟。每次模拟步为 1/120 秒，与显示帧率无关。

没有把所有地形常数改成新值；统一数值积分顺序。固定输入下五种地面在三档显示帧率的完整状态一致到 1e-9；雪地三档位移均为 11.862633 格，末速度均为 2.404199 格/秒，黏土位移均为 30.808208 格。

## 验证与限制

- 完整回归 106 项通过，22.238 秒。新增五种地面/三档帧率/跳跃/体力对照、200 个抖动帧分区、子步跳跃消费、帮助暂停与无效时间检查。
- 三张主题图共 18 条路线改用同一时钟后继续无伤到达终点，各上层平台有奖励，原始数据见 `evidence/2026-11-11_theme_routes_fixed_clock.json`。
- 更新长时审计：15 张地图各 36,000 显示帧，合计 540,000 帧、1,080,000 个固定模拟步；359 种方块各 300 帧，未报告异常、非有限数值、出生重叠或缓存超限。见 `evidence/2026-11-11_fixed_clock_soak.json`。
- 原始加速数据保留 before / after JSON。`scripts/audit_frame_rates.py --legacy --output /tmp/legacy.json` 可复现原显示帧积分；默认使用固定时钟。

固定 120 Hz 增加了低显示帧率时的模拟步数；主循环仍每个显示帧绘制一次。不同帧率下真实用户改变按键的采样时刻仍可能差一个显示帧，测试只对相同持续输入或对齐时间的事件断言状态一致。高帧率画面目前未做运动插值，显示器实测手感仍需验收。
