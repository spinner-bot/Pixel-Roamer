# 地图随机状态与复现一致性

## 复现

三个独立进程分别以随机种子 1 / 999 和正序 / 逆序加载地图，比较全部非默认格子的坐标、方块 ID、元数据 SHA256；同时比较加载前后的进程随机状态。另重新调用宏大旅程、冒险湾公开生成函数。

原实测：地图 2、3、6 的几何哈希发生变化；地图 3、6、9、20、21 改写全局 RNG；宏大旅程、冒险湾重复调用生成函数也改变结果。详见 `evidence/2026-11-11_map_randomness_before.json`。

原因包括：主题大地图用 `hash(str(index))` 摆放海床，受 Python 进程哈希盐影响；多张地图直接使用或重设进程 random；生成函数的随机游标和 `_placed` 集合没有在每次生成前重置。

## 修改与验证

六个相关地图模块分开提交：地图 2 的珊瑚改用固定种子局部 RNG；地图 3、6、9 的装饰使用独立随机源；宏大旅程与冒险湾保留原设计种子 2026 / 42，每次生成重置局部 RNG 和放置集合。运行时事件随机数与地图作者工具不再共享状态。未修改全局方块/buff 数值。

更新审计工具显式改变 `PYTHONHASHSEED`，排除只在同一进程里复制模板而遗漏问题。当前三个独立进程各加载全部 15 张地图，几何哈希全部一致、全局随机状态保持不变；两张公开生成地图再次生成与首次一致。数据见 `evidence/2026-11-11_map_randomness_after.json`。

```bash
python scripts/audit_map_randomness.py --output /tmp/map-randomness.json
```

完整回归 **120 项通过，40.104 秒**，其中包含地图出生点、22 门传送、两个房间出口和全部主题路线。离线预览重新生成后图像没有变化；变化的随机装饰主要位于非出生视野。

此修复使已存测试数据更容易重现，并不证明每张大地图的全部路线都可通关。接下来继续审查窗口失焦/恢复时的计时与输入生命周期。
